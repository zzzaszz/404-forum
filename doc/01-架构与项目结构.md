## 三、分层与请求流

```
浏览器 ──► Vite 代理(/api 去前缀) ──► Spring Boot(10610)
                                          │
                          JwtFilter(校验 token → UserContext)
                                          │
                          Controller ──► Service ──► Mapper ──► MySQL
                                          │                  └─► Redis(计数/缓存)
                                      R<T> 返回
```

- `JwtFilter`：仅 `/api/auth/login`、`/refresh`、`/logout` 放行；其余请求若携带合法 access token，则解析 `userId` 写入
  `UserContext`；未携带则放行但 `UserContext.getUserId()` 为 null（适合匿名浏览场景）。
- 业务层通过 `UserContext.getUserId()` 获取当前用户；写操作（发帖/评论/点赞）需登录态。

## 四、通用 CRUD 约定

每个实体控制器遵循统一五接口（路径 `/{entity}`）：

| 接口 | 方法   | 路径                         | 入参           |
|----|------|----------------------------|--------------|
| 详情 | GET  | `/{entity}/getEntity?key=` | 主键           |
| 分页 | POST | `/{entity}/getPageList`    | `QueryParam` |
| 新增 | POST | `/{entity}/create`         | 实体 JSON      |
| 修改 | POST | `/{entity}/update`         | 实体 JSON      |
| 删除 | GET  | `/{entity}/delete?key=`    | 主键           |

`QueryParam` 支持分页（pageNum/pageSize）、排序（orderBy/OrderType）、`SearchPojo`、`DateRange`、`scenedata`、`searchdata` 等动态过滤。

> 通用 CRUD 面向管理后台；论坛 C 端业务由 `ForumController` 聚合封装（见接口文档）。
