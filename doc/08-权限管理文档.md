# 08 · 权限管理（角色与管理后台）

> 支持登录角色区分（普通用户 / 管理员），仅管理员可见板块管理、用户管理等后台界面与接口。

## 一、角色设计

`User` 表新增 `Role` 字段（迁移脚本：`doc/migration-role.sql`）：

| Role 值 | 含义         |
|--------|------------|
| 0      | 普通用户（注册默认） |
| 1      | 管理员        |

- 注册接口创建的用户 `Role=0`。
- 管理员需**手动**在数据库提权：
  ```sql
  UPDATE User SET Role = 1 WHERE Username = 'admin';
  ```

## 二、登录返回角色

`LoginResponse` 新增 `role` 字段：

```json
{
  "code": 200,
  "data": {
    "token": "...",
    "accessToken": "...",
    "refreshToken": "...",
    "userId": 329905409110446201,
    "nickname": "管理员",
    "avatar": "",
    "role": 1
  }
}
```

前端登录/注册成功后，将 `role` 写入 `localStorage.userInfo`。

## 三、后端权限拦截

`zzz.service.forum.interceptor.AdminInterceptor`：

- 注册到 `/user/**` 路径（`WebConfig.addInterceptors`）。
- 请求前校验：`UserContext.getUserId()` 非空 → 查库取用户 → `Role==1` 放行，否则返回 HTTP 403 + `R{code:403,msg}`。
- 封禁账号（`Status==2`）直接拒绝。

返回示例：

```json
{ "code": 403, "msg": "无权限，仅管理员可访问", "data": null }
```

> 角色实时取自数据库（不缓存在 token），因此提权 / 封禁即时生效，无需重发 token。

## 四、用户管理接口（`/user`，仅管理员）

| 接口    | 方法   | 路径                    | 说明                                                                         |
|-------|------|-----------------------|----------------------------------------------------------------------------|
| 分页查询  | POST | `/user/getPageList`   | 入参 `{keyword?, status?, role?, pageNum, pageSize}`，返回 `PageInfo<UserPojo>` |
| 新增用户  | POST | `/user/create`        | `{username, password, nickname?, role?}`，密码 `PasswordUtils` 加密             |
| 编辑用户  | POST | `/user/update`        | `{id, nickname?, role?}`                                                   |
| 删除用户  | GET  | `/user/delete?key=`   | 逻辑删除，不可删除自身                                                                |
| 重置密码  | POST | `/user/resetPassword` | `{id, password}`，6-32 位                                                    |
| 封禁/解封 | POST | `/user/updateStatus`  | `{id, status}`，status：1正常 2封禁，不可操作自身                                       |

`UserPojo` 字段：`id, username, nickname, avatar, status, role, lastloginip, lastloginat, createdat`（不含密码）。

## 五、前端权限控制

### 5.1 角色读取

`localStorage.userInfo.role`：`1` 为管理员。

### 5.2 路由守卫（`router/index.js`）

- `meta.requiresAdmin: true` 的路由（`/board`、`/user`）校验 `role===1`，否则跳回首页。
- 普通用户直接访问管理路由会被拦截。

### 5.3 侧边栏菜单（`MainLayout.vue`）

- 「管理」子菜单（板块管理 + 用户管理）通过 `v-if="isAdmin"` 仅对管理员渲染。

### 5.4 403 处理（`request.js`）

- 响应 `code===403` 时 `ElMessage.error` 提示「无权限」并 reject，不触发登录跳转。

### 5.5 用户管理页（`UserManage.vue`）

- el-table 展示：账号、昵称、角色、状态、登录IP、登录时间、注册时间。
- 操作：编辑（昵称/角色）、重置密码、封禁/解封、删除、新增用户。
- 顶部统计卡片：总数 / 正常 / 封禁 / 管理员数。

## 六、数据库迁移顺序

1. `doc/atest.sql` 建表
2. `doc/migration-account-password.sql` 账号密码字段
3. `doc/migration-role.sql` 角色字段
4. `doc/seed.sql` 板块种子
5. 注册一个账号 → `UPDATE User SET Role=1 WHERE Username='xxx'` 提权为管理员

## 七、安全约束

- 管理员不能删除 / 封禁自身账号。
- 管理接口双重防护：前端路由守卫 + 后端 `AdminInterceptor`（以后端为准）。
- 密码全程哈希存储，重置密码也走 `PasswordUtils.encode`。
